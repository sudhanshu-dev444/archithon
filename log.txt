4.2 Edge AI Pipeline (in Web Workers, never on the main thread)


Model manager: download models once when online, cache in Cache Storage/OPFS, verify SHA-256 checksums, show size/progress, allow selecting a "lite" profile for low-RAM devices (tiny Whisper + smaller LLM). Detect device memory (navigator.deviceMemory) and pick a profile automatically.

Job queue: a persistent local job queue (ai_jobs table) with states queued → running → needs_review | failed, resumable after tab close/crash, with concurrency = 1 for heavy models to avoid OOM.

Pipeline: Whisper transcript and/or OCR text → text normalizer (merge, de-duplicate, tag source + confidence + timestamps) → LLM structured extraction with a strict JSON schema (grammar-constrained / schema-validated decoding; retry once with a repair prompt; fall back to rule-based regex extractor for vitals/medications if the LLM fails) → validator (units, plausible ranges, drug-name fuzzy match against a bundled formulary list) → draft case file.

4.5 Sync Engine (PRIMARY DELIVERABLE — build with the most rigor)
Client side


Operation-log (outbox) pattern: every user mutation is written in ONE IndexedDB transaction together with an Operation record: {op_id (UUIDv7), device_id, entity_type, entity_id, op_type (create|update|delete|attach), base_version, patch (field-level diff), payload_encrypted, client_ts (HLC), seq_no (per-device monotonic), status (pending|in_flight|acked|conflicted|failed), attempts, next_retry_at}.

Network detection: do not trust navigator.onLine alone. Combine online/offline events + a lightweight authenticated GET /health probe with timeout, hysteresis (require N consecutive successes before "online"; M failures before "offline"), and connection quality estimate. Expose a ConnectivityState store (offline | flaky | online) to the UI. Use Background Sync API where supported, with a foreground timer fallback.

Push loop: when online, send outbox ops in seq_no order in batches (POST /sync/push). Mark in_flight before sending; on ambiguous failure (timeout, dropped connection) keep the op and retry with the SAME op_id. Exponential backoff with jitter, max attempts, and a circuit breaker; permanent 4xx errors move the op to failed with a visible reason.

Pull loop: GET /sync/pull?since=<server_cursor> returns changes with a monotonically increasing server_seq; apply them in a transaction, update the cursor atomically. Support pagination and resumable pulls.

Crash safety: state transitions must be crash-consistent (e.g., kill the tab mid-push, restart, no loss, no duplicates).
Server side (FastAPI + PostgreSQL)


Idempotency: table processed_operations(op_id PRIMARY KEY, device_id, result_json, server_seq, processed_at). Within a single DB transaction: check op_id; if already processed, return the stored result unchanged (same response, no side effects); otherwise apply and insert. Also support an Idempotency-Key header at the request/batch level.

Versioning / optimistic concurrency: each entity row has version (int) and server_seq. An update op carries base_version. If base_version == current version → apply, increment version. If not → concurrent modification detected.

Conflict detection: perform a three-way, field-level merge: base (reconstructed from the version history table entity_versions), server current, client patch.


Non-overlapping field changes → auto-merge, record merge in the audit log, bump version.

Overlapping changes to the same field with different values → explicit conflict (never last-write-wins silently). Store in conflicts with base/server/client values and status open.

Delete vs. update → conflict. Duplicate create (same natural key e.g. patient national ID) → conflict/merge-candidate.

Clinical safety fields (allergies, medications, diagnoses) are never auto-merged on overlap; they require human resolution.

Append-only collections (e.g., vitals readings, attachments, encounter notes) merge as set-union by id.

Conflict resolution workflow: GET /conflicts, POST /conflicts/{id}/resolve with strategy keep_server | keep_client | manual_merge (+ resolved payload) and a mandatory resolved_by and reason. Resolution creates a NEW version (history is never rewritten), is itself idempotent, is audit-logged, and propagates to all devices on the next pull. The client shows a dedicated Conflict Resolution screen: side-by-side diff (base / yours / theirs), per-field choice, and "mark resolved".

Ordering & atomicity: batch processing is per-operation atomic; a failed op does not roll back earlier successful ops; the response lists a per-op status (applied | duplicate | merged | conflict | rejected) so the client reconciles precisely.

Dependencies: ops on the same entity apply in seq_no order per device; if an earlier op is conflicted, dependent later ops on that entity are held (blocked) until resolved.

Clock handling: never trust client clocks for ordering; use the server server_seq for ordering and the HLC only as a hint/tiebreaker.

Attachments: large blobs (audio/images) uploaded via resumable chunked upload with content hash for dedup, referenced by ops.

Rate limiting + request size limits + schema validation on all sync endpoints.
Verifiability


Expose GET /sync/verify?entity=... returning the hash of canonical state; the client can compare local vs. server Merkle/hash digests per patient to prove convergence.

Ship a Sync Inspector dev screen: outbox contents, op states, retry timers, cursor, last errors, conflict list, and a "simulate offline / flaky network / duplicate delivery / server timeout after commit" toggle.
